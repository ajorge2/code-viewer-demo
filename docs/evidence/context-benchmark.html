What prewarming changed on the question path.

The original benchmark compared the same context pipeline in cold, prewarmed, and immediate-repeat states. Its raw artifact and runner make the latency result directly inspectable.

Supported conclusion

Repository-wide LLM summarization moved off the interactive path, reducing median context-preparation latency 61% (33.2s to 12.9s) across three fixed questions in a 36-file, 9.7K-line self-benchmark. Immediate repeat queries prepared context in 0.81ms.

Original measurement

Immediate repeat0.810 ms6,280.933 ms1

Generated 2026-08-01 on an Apple M2 with Node 23.7.0. Each state contains one observation for each of three fixed questions.

Exact calculation

(33,223.190 − 12,865.299) / 33,223.190 = 61.276%

The separate prewarm took 18,857.843ms p50 and made 59 calls p50. The benchmark therefore reports the interactive question path and the one-time prewarm as separate stages.

What is now reproducible

The repository contains the original dated result, all three fixed questions, isolated cache reset logic, per-phase instrumentation, telemetry tests, and a schema-v2 runner. The updated runner records provider-reported tokens by model and phase and keeps foreground context work separate from the one-time prewarm.

A dependency-complete dry run resolves all three targets and reports the current repository's file, line, and byte scale without making model calls.

Limits

  • One repository and three observations per state.
  • Different fixed questions contribute to each p50; this is not repeated timing of one request.
  • The recorded source state was commit afc99fe plus uncommitted benchmark instrumentation.
  • The measurement isolates pre-answer context preparation; answer generation is separate.
  • Schema v1 cannot establish dollar cost because it lacks token usage.
