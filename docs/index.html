Semantics-first NLP · repository-disjoint evaluation

Learning what code means from how developers describe change.

CodeArchitect learns reusable software concepts from developer-written change descriptions, verifies that each concept corresponds to recurring AST structure, and applies the resulting taxonomy to code from repository families excluded from discovery. This page joins the research method to the human-reviewed decision evidence behind the final operating policy.

The research question

Can developer language produce recognizable concepts—such as configuration, testing, and version compatibility—while code structure independently verifies that each concept corresponds to a recurring implementation pattern?

The experiment separates meaning discovery from structural verification: message-object phrases create the semantic clusters; AST evidence determines whether a proposed concept has a bounded, recurring implementation pattern.

What the taxonomy learned

The retained hierarchy includes application configuration, automated software testing, version compatibility and metadata, state flags, test-suite infrastructure, configuration setup and paths, test-case artifacts, version lookup, and unit-test infrastructure.

Each concept is traceable to its message-derived members, repository provenance, semantic centroid, and recurring AST evidence. Recursive child concepts survive only when their parent has already passed both the semantic and structural gates.

Held-out result and human calibration

The original notebook used schema-constrained model judgments to audit the complete pipeline. The later evidence pass kept the taxonomy and held-out predictions fixed, blinded the producing method and score, and supplied new human labels for every prediction accepted by either semantic policy or the exact-token baseline.

Engineering result

Separately from taxonomy quality, a dated self-benchmark measured the product's context-preparation path. Content-addressed prewarming reduced median pre-answer context latency from 33.2 seconds cold to 12.9 seconds prewarmed—a 61.3% reduction—across three fixed questions on a 36-file, 9.7K-line repository. An immediate repeat prepared context in 0.81 milliseconds.

Limitations. The 14-concept vocabulary is concentrated in configuration, testing, versioning, and state metadata. The human adjudication is new, but the holdout and earlier model judgments had already informed development. The evaluation measures precision among accepted predictions—not recall over all software concepts, end-user comprehension, or downstream product outcomes. The latency result is a three-question self-benchmark on one repository.
